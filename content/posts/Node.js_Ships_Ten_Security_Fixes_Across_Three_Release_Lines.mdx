On October 21, the Node.js project shipped coordinated security releases for its three supported lines: v26.12.1, v24.22.1 (the current LTS) and v22.23.4. According to the project's advisory, the highest severity is High, and four of the ten fixed issues carry that rating. If you run Node in production, this is an upgrade you should schedule now rather than at the next maintenance window.

## What was fixed

The advisory lists ten issues. The four High-severity ones are the most relevant to most teams:

- **DNS NUL truncation (CVE-2026-105482).** Hostnames containing a NUL byte are truncated when passed to c-ares, so a name like `attacker.example` followed by a NUL and a trusted suffix queries only the attacker's name. The advisory says an app that checks a hostname against an allowlist and then calls `dns.resolve*()` can end up acting on records for a different name. It affects all three lines.
- **TLS fullwidth-digit IP bypass (CVE-2026-105483).** `tls.checkServerIdentity()` did not recognize hosts written with fullwidth digits as IP addresses, so it matched them against DNS names instead. Per the advisory this is a regression from an earlier fix and affects 26.x and 24.x only.
- **TLS leading-zero IPv4 bypass (CVE-2026-106069).** URL normalization reads a leading-zero address as octal, while some operating system resolvers read it as decimal. The server at the connected address could then be authenticated with a certificate issued for a different IP.
- **Brotli decoder out-of-bounds write (CVE-2026-111497).** The advisory says malformed Brotli data passed to `node:zlib` can corrupt process memory, with crash, memory disclosure or remote code execution as possible outcomes.

## The medium and low issues

The medium-severity items are subtler but still worth reading:

- A keep-alive HTTP socket could parse unsolicited data as the response to a later request if that data arrived while the event loop was busy (CVE-2026-105481).
- Non-canonical IPv4 spellings such as `0x7f.0.0.1` could be matched against numeric DNS subject alternative names (CVE-2026-106072).
- The caches behind `crypto.randomUUID()`, `randomUUIDv7()` and `randomInt()` are captured by build snapshots and single executable applications, so every process started from one repeats the same values (CVE-2026-106074).

On the low end, the advisory describes a ZIP parsing issue and a permission-model wildcard over-grant that affect 26.x only, plus a bypass in `fs.realpathSync()` that lets code under `--permission` probe paths outside its allowed directories (CVE-2026-106073).

## A pattern worth noticing

Several of these are described as incomplete fixes of earlier CVEs: the DNS NUL issue extends an earlier `dns.lookup()` fix, the keep-alive issue follows a prior socket fix, and the fullwidth-digit bug is a regression from an earlier TLS patch. That is a useful reminder that input canonicalization, such as IP address parsing and hostname handling, is a place where one patch rarely closes the whole class of bug.

## What to do

1. Upgrade to v26.12.1, v24.22.1 or v22.23.4. The advisory also notes that end-of-life lines are always affected by security releases and should move to a supported version.
2. Audit places where you make security decisions from DNS, TLS or Brotli input, especially allowlists keyed on hostnames or IP-like strings.
3. If you build snapshots or single executable applications, rebuild them after upgrading, and avoid calling the random helpers during the build.
4. If you rely on the permission model as a boundary, avoid wildcard grants at the root of the tree and do not treat `fs.realpathSync()` as an access control.

The advisory also lists interim mitigations if you cannot upgrade immediately, for example rejecting hostnames containing NUL bytes before DNS calls and not decompressing untrusted Brotli input. The page labels those as suggestions rather than official guidance, so treat them as stopgaps.
